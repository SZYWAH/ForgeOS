# ForgeOS 项目目标

## 一句话定位

ForgeOS 是一个帮助个人开发者管理多项目研发上下文，并让自己和 Codex 随时理解项目身份、当前状态、研发历史、成果与下一步的本地优先研发记忆助手。

## 核心用户价值

- 每个项目拥有独立的身份、目标、技术栈和研发记忆，避免项目之间串联。
- Codex 与 Git 的只读活动可整理为待审核状态，用户确认后才成为正式事实。
- 研发历史按活动聚合，保留目标、过程、结果、验证、提交和交接信息。
- 项目成果可沉淀为结构化记录，用于复盘、简历和面试展示。
- AI 与 MCP 可以读取受治理的项目上下文，但不能修改 ForgeOS、代码或 Git。
- 公开 GitHub 仓库可先进行规则或 AI 增强分析，再经人工审核导入为个人项目。

## 产品边界

ForgeOS 坚持：

- 本地优先，SQLite 是结构化事实来源。
- 系统观察与人工确认明确分离。
- Project 级数据隔离，跨项目查询和来源绑定必须被拒绝。
- Git、GitHub、Codex Activity 与 MCP 默认只读。
- AI 只能在用户主动触发时分析，失败时回退确定性规则。

ForgeOS 不提供：

- Codex 自动执行、Agent 或 MCP 写入。
- 自动修改代码、Git Commit、Push、Merge、Fork 或 Pull Request。
- 未经用户确认自动更新 Snapshot、Session、Achievement 或 Project。
- 默认执行、安装或运行第三方 GitHub 项目代码。

## 当前交付基线

- 当前公开预览版：`v0.2.0` Windows x64。
- 当前功能基线：D9 GitHub Project Intelligence 与人工导入闭环。
- 当前收尾阶段：D9.4.1 AI 服务工作台与表单视觉修复。
- 下一阶段：D10.0 GitHub Clone & Reproduction Architecture Freeze，仅冻结架构、安全和交互，不直接实现克隆或执行。

## 成功标准

- 用户能在 60 秒内理解任一项目的定位、当前目标、问题和下一步。
- Codex 能通过只读 MCP 获取正确项目上下文，且不混入其他项目数据。
- 自动整理内容始终可追溯，并在进入正式事实前经过人工审核。
- 所有外部内容在持久化、AI 或 MCP 输出前经过预算、脱敏和来源治理。
- 发布、测试、实机验收和外部推送状态分别报告，不把计划当作已验证结果。
