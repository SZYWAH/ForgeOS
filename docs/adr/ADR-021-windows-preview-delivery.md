# ADR-021：Windows 预览交付与 MCP 一键接入

## 背景

ForgeOS 已具备桌面端和只读 MCP，但用户仍需自行构建、查找 MCP 路径并修改 Codex 配置。该流程不适合 v0.1.0 预览分发，也容易把开发目录写入长期配置。

## 候选方案

1. 单独发布桌面程序和 MCP，由用户手动配置。
2. 把 MCP 加入 PATH，并长期运行后台服务。
3. 把 MCP 作为 Tauri Sidecar 打进 NSIS，由桌面设置页调用官方 Codex CLI 管理 STDIO 配置。

## 决策

采用方案三：Windows x64 当前用户 NSIS 安装包包含 `forgeos-mcp.exe`；用户在应用设置中主动连接 Codex。配置修改前备份，写入后复核，失败时回滚。同名配置冲突必须确认。升级通过固定的 `/FORGEOS_UPGRADE=1` 标记保留连接；普通卸载仅删除完全匹配的自有配置。

WebView2 采用在线 Bootstrapper，安装包不签名，不提供自动更新器，也不单独发布 MCP。

## 优点

- 一个小型安装包完成桌面端与 MCP 交付。
- 使用 Codex 官方 CLI，避免自行解析和重写 TOML。
- MCP 按需由 Codex 通过 STDIO 启动，无端口、服务或 PATH 污染。
- 所有权判断、备份、验证和回滚降低误删用户配置的风险。
- 升级、普通卸载和重装具有明确边界。

## 缺点

- 未签名安装包可能触发 SmartScreen。
- 缺少 WebView2 的电脑安装时需要网络。
- 固定 Tauri 2.11.4 NSIS 模板需要在升级 Tauri 时重新审计。
- Codex CLI 不可用时无法一键配置。

## 长期影响

后续升级 Tauri、改变安装目录或调整 Codex CLI 输出结构时，必须重新运行安装、升级、冲突和卸载验收。代码签名、自动更新和更多架构安装包可以独立评估，但不能削弱 MCP 只读边界或配置所有权检查。
